# RFC 0008: Edition 2027 — One Way, Checked, Measured

- **Status:** accepted (in development; rules may change until announced stable)
- **Author:** Forge maintainers
- **Date:** 2026-10-11

## Summary

Edition 2027 is the first source-breaking edition of Forge. It removes
duplicate ways to write the same thing, turns silent coercions and ignored
type annotations into errors, and adds the expression forms that make the
remaining syntax enough. Projects opt in with `edition = "2027"` in
`forge.toml` or `forge --edition 2027`; edition 2026 code keeps running
unchanged on every future release. A migration command rewrites 2026 code
to 2027.

The edition is driven by a measurement, not taste: an evaluation harness
(`eval/`) measures how often a model writes a correct Forge program on the
first try, with only `llms.txt` as context, and compares that with Python on
the same tasks. Every 2027 change must not lower that rate, and the
failures it finds decide what changes next.

## Motivation

Forge's best use is code that AI agents write and hosts run in a sandbox.
For that, the language must be easy to write correctly on the first try
and must fail loudly when it is not. Today:

- There are two spellings for most things (`let`/`set ... to`,
  `else`/`otherwise`/`nah`, `fn`/`define`, `await`/`hold`, `yield`/`emit`),
  plus joke builtins (`sus`, `bruh`, `slay`, ...). Each doubles what a
  reader and a model must know, and models mix them.
- `"a" + 1` is `"a1"`; a function declared `-> Int` can return a String;
  generics are parsed and ignored. Bugs surface far from their cause.
- `match` is a statement only, without guards or or-patterns, so simple
  value selection needs a mutable variable.
- Six error mechanisms overlap (`Result`, `?`, `try/catch`, `must`, `safe`,
  `check`).

## Design

### 0. Editions are real (foundation, done)

`semantics::edition`: `Edition::{E2026, E2027}`, `current()`, a process
default set by the CLI (`--edition` > `forge.toml` > 2026) and a per-thread
override (`scope`) used by `Sandbox::edition` and carried into spawned
threads by `permissions::inherit`. The edition is read when a program is
*prepared* (parser, compiler, interpreter construction), never per
operation. Each gated rule records the edition in what the engine keeps for
the run (the chunk, the interpreter) so imports and forks agree.

Imports: a module is parsed under the importing run's edition (per-package
editions are future work, see Open Questions).

### 1. Evaluation harness (`eval/`)

- ~100 tasks across: basics, strings, collections, structs/ADTs, error
  handling, JSON/CSV, closures/functional, algorithms, concurrency,
  HTTP (local server + client), file I/O. Each task: a prompt, stdin/args,
  expected stdout (exact or normalized), and reference solutions in Forge
  and Python that CI runs on both engines so the tasks stay valid.
- Providers: `anthropic` (API key from the environment), `command` (any
  CLI reading the prompt on stdin), `dir` (pre-generated solutions, e.g.
  from blind agents).
- Context modes: `none`, `llms` (llms.txt), `llms+errors` (one repair
  round with the compiler's JSON diagnostics: measures how good the error
  messages are, separately from first-try correctness).
- Reports: pass@1 per category, per language, per edition; every failure
  is classified (syntax error, wrong builtin/argument order, type error,
  wrong output, timeout) with the diagnostic code, so the next language fix
  is chosen from data.

### 2. Strict operators (2027)

`+` with a String and a non-String operand is an error (E00xx, hint: use
`str(x)` or `"{x}"` interpolation). Both engines through
`semantics::binary`; the type checker reports it statically as an error in
2027. Other implicit conversions get the same audit (`==` across types
stays a plain `false`).

### 3. `match` as an expression, guards, or-patterns (all editions)

```forge
let size = match n {
    0 => "none",
    1 | 2 => "few",
    x if x < 10 => "some",
    _ => "many",
}
```

Additive syntax (previously a syntax error), so it is not edition-gated.
Both engines, type checker (exhaustiveness counts guards as non-covering),
formatter, syntax index/LSP, `llms.txt`, spec.

### 4. Annotations are enforced (2027)

In 2027 a type-checker error against a *declared* type (argument, return,
`let x: T`) is an error, not a warning, and annotated function boundaries
are checked at run time (the `--strict` instrumentation, on by default for
annotated code). Unannotated code stays gradual. Generic parameters are
checked for consistency at each call (`fn first<T>(xs: [T]) -> T` called
with `[Int]` returns `Int`).

### 5. One syntax (2027)

Removed in 2027 (a syntax error with a fix-it naming the replacement):
`set x to`, `set mut x to`, `change x to`, `define`, `otherwise`, `nah`,
`forge` (async fn), `hold`, `emit`, `grab ... from`, `repeat n times`,
`safe { }`, `must expr`, `check x is ...`; and the builtins `say`, `yell`,
`whisper`, `sus`, `bruh`, `bet`, `no_cap`, `ick`, `cook`, `yolo`, `ghost`,
`slay`. Kept: `println`/`print`, `fn`, `else`, `async`/`await`, `yield`,
`for x in range(n)`, `try`/`catch`, `Result`/`?`/`unwrap`, `assert*`,
`when`, `retry`, `timeout`, `schedule`, `watch`, `ask`, decorators.

`let {a, b} = obj` and `let [x, ...rest] = arr` become the destructuring
forms in all editions (additive); `unpack ... from` is removed in 2027.

`forge fix --edition 2027 [paths]` rewrites 2026 code to 2027 token by
token (comments and layout preserved) and reports anything it cannot
rewrite mechanically.

## Alternatives Considered

- **Deprecation warnings in 2026 instead of an edition.** Breaks the
  stability promise for code that never opted in; warnings also train
  models on both forms.
- **Keep the natural syntax as the one syntax.** Models overwhelmingly
  write C-family syntax first; the eval will confirm or refute this.
- **Remove the interpreter first.** Orthogonal; the edition must work on
  both engines while both exist.

## Open Questions

- Per-package editions for imported modules (STABILITY.md promises it).
- Whether `when` survives once `match` is an expression.
- Integer division (`7 / 2 == 3`): measure before changing.

## Implementation Notes

Workstreams (one branch each, merged into one PR):

| # | Workstream | Main files |
|---|---|---|
| 0 | Edition plumbing | `src/semantics/edition.rs`, `main.rs`, `sandbox.rs`, `permissions.rs` |
| 1 | Eval harness | `eval/`, `tests/eval_tasks.rs` |
| 2 | Strict operators | `src/semantics/mod.rs`, both engines, typechecker |
| 3 | `match` expressions | parser, both engines, typechecker, formatter, LSP |
| 4 | Enforced annotations | `src/typechecker/`, `main.rs`, `sandbox.rs` |
| 5 | One syntax + `forge fix` | lexer/parser gating, `builtins_registry.rs`, new `fix` command |

Every 2027 rule: tests on both engines under `tests/edition2027/` (run with
`forge --edition 2027 test`), the 2026 behaviour pinned by a test, an entry
in `docs/editions/2027.md`, `llms.txt` updated for the canonical form.
