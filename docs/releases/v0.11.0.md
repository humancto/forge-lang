# Forge 0.11.0

Released 2026-10-11. The full list of changes is in
[CHANGELOG.md](../../CHANGELOG.md#0110---2026-10-11). This page summarizes
it and lists what may need attention when upgrading from 0.9.0 or 0.10.0.
(0.10.0 was prepared but not published; its changes ship in this release.
See [v0.10.0.md](v0.10.0.md).)

## Highlights

### Measured, then fixed: first-try correctness

Forge now ships an evaluation harness (`eval/`): 103 realistic tasks, each
with a Forge and a Python reference that CI runs on both engines and both
editions. It measures how often a model writes a correct Forge program on
the first try, with only [`llms.txt`](../../llms.txt) as documentation, and
classifies every failure by its error code. Every language change in this
release was chosen from that failure table.

| Blind solvers, 103 tasks | Forge (2027) | Python |
|---|---:|---:|
| Before (v0.10.0, its `llms.txt`) | 31.1% | 98.1% |
| This release, fresh solvers | **100%** | 98.1% |

The log of what each fix was worth is in
[`eval/RESULTS.md`](../../eval/RESULTS.md). Run it against a real model
with `python3 eval/forge_eval.py generate --provider anthropic ...`.

### Edition 2027 (preview)

Opt in with `edition = "2027"` in `forge.toml` or `forge --edition 2027`.
Edition 2026 code keeps working unchanged. In 2027:

- **One syntax.** The natural-language forms (`set x to`, `define`,
  `otherwise`, `say`, `safe`, `must`, `check`, …) and the GenZ builtins
  are removed; each gives an error (E0035) naming the replacement.
  `forge fix --edition 2027` rewrites 2026 code for you, keeping comments
  and layout.
- **Strict `+`.** `"total: " + n` is an error (E0034); use `"total: {n}"`
  or `str(n)`.
- **Declared types are enforced.** A contradiction of an annotation is an
  error before the program runs, and annotated function boundaries are
  checked at run time (imported modules included). Unannotated code is
  unaffected and costs nothing.
- **`push` is pure.** `push(xs, v)` returns a new array and never changes
  `xs`; write `xs = push(xs, v)` (or the method form `xs.push(v)`, which
  appends to a `let mut` variable in place). A discarded `push(...)` is
  T0019. `pop` keeps its meaning (it removes the last element), so stack
  loops still terminate.

### New in every edition

- `match` is an expression, with guards (`x if x > 0 =>`) and or-patterns
  (`1 | 2 =>`).
- `let {a, b} = obj` and `let [x, ...rest] = arr`.
- Top-level functions can be called above their definition.
- `[1, 2] + [3]` concatenates arrays.
- Global `abs`, `min`, `max`, `round(x, digits?)`, `floor`, `ceil` and
  `to_fixed(x, digits)` (`to_fixed(2.5, 2)` is `"2.50"`).
- `json.compact(x)`; `json.parse` keeps the document's key order.
- Interpolations may contain string literals: `"{join(xs, ", ")}"`.
- Common words such as `order`, `from`, `to`, `limit`, `safe` and `emit`
  can be used as names.
- Programs read piped input with `fs.lines("/dev/stdin")`, also under
  `--sandbox`.

### Faster

- `xs = push(xs, v)` appends in place on the VM instead of copying the
  array: 100k appends went from 24.8 s to 0.017 s.

### Fixes

- An intermittent JIT crash: calls between compiled functions could not
  reach code compiled more than 2 GiB away.
- `if c == QUOTE {` no longer parses as a struct literal.
- `get(m, ".txt", 0)` finds an exact key containing dots.
- `http.post` sends a String body as is instead of JSON-encoding it again.
- `forge run app.fg | head` exits quietly.

## Upgrading

- **Bytecode files.** `.fgc` files are format 1.4 (they record their
  edition). This release reads older files; older releases refuse 1.4.
- **`json.parse` key order.** Objects now keep the document's order. Code
  that relied on alphabetical order from `json.parse` should sort keys
  explicitly (`sort(keys(obj))`).
- **HTTP string bodies.** `http.post(url, { body: "text" })` now sends
  `text` (Content-Type `text/plain`) instead of the JSON string `"text"`.
- **Function hoisting.** Only programs that previously failed with an
  undefined-function error change behaviour.
- **Edition 2027 is a preview.** Its rules may still change before it is
  announced stable; pin `edition = "2026"` (the default) for production.
