# Edition 2027 (in development)

Opt in with `edition = "2027"` under `[project]` in `forge.toml`, or
`forge --edition 2027 run app.fg`. Edition 2026 code is unaffected.
Design and rationale: [RFC 0008](../../rfcs/0008-edition-2027.md).
`forge fix --edition 2027` migrates code (see [Migrating](#migrating)).

Edition 2027 is a **preview**: its rules may still change until it is
announced stable.

### Strict `+`: no implicit conversion to String

**What changed.** In edition 2026, `+` with a String on one side and any
other value on the other converts that value to text: `"a" + 1` is `"a1"`,
`"total: " + null` is `"total: null"`. In edition 2027, `+` concatenates only
two Strings; a String and a non-String is an error. Numbers still add as
numbers, and every other operator is unchanged (`"a" * 2` and `"a" < 1`
were already errors; `==` across types stays a plain `false`).

**The error.** At run time, on both engines, `E0034`: `cannot add String
and Int` (the message names both operand types, left first), with the hint
`+ does not convert to String implicitly (edition 2027); convert with
str(x), or interpolate: "{x}"`. `catch e` sees `e.code == "E0034"`.

When the checker can see both types (`println("n=" + 1)`), the program does
not start: `T0005 operator '+' cannot be applied to String and Int`, an
error in edition 2027 even without `--strict`.

**Migration.** Use interpolation or an explicit conversion:

```forge
let n = 3
println("items: {n}")          // was: "items: " + n
println("items: " + str(n))    // also fine
```

A `.fgc` file keeps the edition it was compiled under: compiled with
`--edition 2027` it rejects mixed `+` wherever it runs, and a file from
before editions (format < 1.4) runs as edition 2026.

**Tests.** `tests/edition2027/strict_concat_test.fg` (2027, both engines),
`tests/string_concat_2026_test.fg` (2026 pin), `tests/errors/E0034_*.fg`,
`edition_2027_strict_string_concat` in `tests/error_codes.rs` (type error,
`.fgc` editions), sandbox and HTTP-fork tests in `src/sandbox.rs` and
`src/vm/serve_tests.rs`.

Code in this repository that relies on the 2026 conversion (to rewrite
with `forge fix`): `tests/parity/supported/string_ordering.fg` (`"n" + 1`),
`tests/safety_test.fg` (`1 + "x"` inside `safe`, expected to fail anyway).
### One syntax

Edition 2027 has one way to write each thing. The natural-syntax forms of
edition 2026 are removed: each is a syntax error **E0035** whose hint names
the exact replacement, and its word is no longer a keyword (`set`, `check`,
`hold`, `safe`, ... are ordinary names in 2027: `let set = 1` works).

| Removed (2026) | Write instead (2027) | Error |
|---|---|---|
| `set x to v` | `let x = v` | E0035 |
| `set mut x to v` | `let mut x = v` | E0035 |
| `change x to v` | `x = v` | E0035 |
| `define f(a) { }` | `fn f(a) { }` | E0035 |
| `forge f() { }` / `forge fn f() { }` | `async fn f() { }` | E0035 |
| `otherwise { }`, `nah { }` (also `otherwise ->` in `when`) | `else { }` (`else ->`) | E0035 |
| `hold expr` | `await expr` | E0035 |
| `emit value` | `yield value` | E0035 |
| `grab r from url` / `grab r from url with opts` | `let r = fetch(url)` / `let r = fetch(url, opts)` | E0035 |
| `repeat n times { }` | `for _ in range(n) { }` | E0035 |
| `unpack {a, b} from obj` | `let {a, b} = obj` | E0035 |
| `unpack [x, ...rest] from arr` | `let [x, ...rest] = arr` | E0035 |
| `unpack (a, b) from t` | `let (a, b) = t` | E0035 |
| `safe { ... }` | `try { ... } catch e { }` | E0035 |
| `must expr` | `unwrap(expr)` | E0035 |
| `check x` | `assert(x)` | E0035 |
| `check x is not empty` | `assert(len(x) > 0)` | E0035 |
| `check x between lo and hi` | `assert(x >= lo && x <= hi)` | E0035 |
| `say x` | `println(x)` | E0035 |
| `yell x` | `println(upper(str(x)))` | E0035 |
| `whisper x` | `println(lower(str(x)))` | E0035 |

The builtins below are removed: in 2027 they are not defined, so a use is
an unknown name — **T0006** from the type checker, **E0003** at run time —
whose hint names the replacement.

| Removed builtin | Write instead |
|---|---|
| `say(x)`, `yell(x)`, `whisper(x)` | `println(x)`, `println(upper(str(x)))`, `println(lower(str(x)))` |
| `sus(x)` | `println(x)` (sus printed to stderr and returned `x`) |
| `bruh(msg)` | `assert(false, msg)` |
| `bet(cond, msg)` | `assert(cond, msg)` |
| `no_cap(a, b)` | `assert_eq(a, b)` |
| `ick(cond, msg)` | `assert(!cond, msg)` |
| `ghost(f)` | `f()` |
| `cook(f)` | `f()`, timed with `time.now()` if needed |
| `yolo(f)` | `try { f() } catch e { }` |
| `slay(f, n)` | a loop timing `f()` with `time.now()` |

Kept in every edition: `println`/`print`, `fn`, `else`, `async`/`await`,
`yield`, `for x in range(n)`, `try`/`catch`, `Result`/`?`/`unwrap`,
`assert*`, `when`, `retry`, `timeout`, `schedule`, `watch`, `wait`, `ask`,
`download`, `crawl`, decorators — and the natural type-definition words
(`thing`, `power`, `give`, `craft`), which RFC 0008 does not remove.

New in **all** editions (additive, so not gated): the natural, query and
innovation words (`order`, `from`, `to`, `limit`, `where`, `select`, `safe`,
`check`, `emit`, `times`, `wait`, ...) are *soft keywords* — keywords only
where their construct can start, ordinary names elsewhere (`let order = 1`,
`fn safe(x) { }`, `{ limit: 5 }`); in 2027 the removed ones are not
keywords at all. Only the core words (`let`, `fn`, `if`, `for`, `in`,
`match`, `try`, `await`, ...) and type names stay reserved.

Also new in all editions: `let` destructures
objects and arrays, like `unpack` did, with renaming and `let mut`:

```forge
let {a, b: renamed} = { a: 1, b: 2 }
let [first, ...rest] = [1, 2, 3]
let mut [x, y] = [1, 2]
```

Missing fields and items bind `null`. A `let` pattern binds immutable names
unless it is `let mut`. (`unpack` binds immutable names on both engines;
before this change the interpreter alone made them mutable.)

**Replacements that are not exactly equivalent.** `forge fix` uses them
anyway; review these when a program relied on the difference:

- `must e` passed a plain non-null value through and failed on `null`;
  `unwrap(e)` accepts only a `Result` or an `Option`. Error messages differ
  (`must failed: ...` vs `unwrap() on Err: ...`).
- `check` failed with E0022 `check failed: ...`; `assert` fails with E0021
  `assertion failed: ...`. `check x is not empty` passed for any value that
  is not an empty string, an empty array or `null` (so `5` and `{}`
  passed); `len(x) > 0` fails for `{}` and is an error for numbers.
- `safe { }` as the last statement of a function made the function return
  the block's value; `try { } catch _ { }` does not. `forge fix` reports
  `safe { }` used as a value instead of rewriting it.
- `bruh`, `bet`, `no_cap`, `ick` raised `BRUH: ...` (E0025), `LOST THE BET:
  ...`, `CAP DETECTED: ...`, `ICK: ...`; the `assert*` replacements raise
  E0021 with their own wording. `bet`/`ick` treated a non-Bool condition as
  `true`; `assert` uses truthiness.

Tests: `tests/edition_one_syntax.rs` (every form and builtin, both engines,
both editions), `tests/edition2027/one_syntax_test.fg`,
`tests/errors/E0035_removed_syntax.fg`.

## Migrating

```
forge fix --edition 2027                  # rewrite every .fg under the current directory
forge fix --edition 2027 src/ app.fg      # files or directories
forge fix --edition 2027 --diff .         # show a unified diff, write nothing
forge fix --edition 2027 --check .        # exit 1 if anything needs rewriting
forge fix --edition 2027 --set-edition .  # also set edition = "2027" in ./forge.toml
```

`forge fix` reads edition 2026 code and rewrites it token by token:
comments, blank lines and layout are kept, and running it again changes
nothing. It reports what it cannot rewrite mechanically, as
`file:line:col: ...`, and leaves it untouched (exit status 1): `safe { }`
used as a value, `check x is <anything but "not empty">`, removed forms
inside string interpolations, and the builtins `sus`, `cook`, `yolo` and
`slay` (their output or error handling has no exact equivalent). Calls of a
removed builtin are only rewritten when the name is the builtin, not a user
definition of the same name.

Over this repository's own corpus (`examples/`, `tests/*.fg`,
`tests/parity/`), `tests/forge_fix.rs` checks that every fully rewritten
file parses under 2027, is a fixed point, and prints the same output under
2027 as the original under 2026.
